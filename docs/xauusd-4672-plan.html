Fix the frame first

On IB and Geometric engines the lattice is hardcoded to syminfo.mintick, so on gold your frame maxes out at ±$0.50 — and Ticks Per Row is ignored outside Footprint mode. That is why W‑POC, VAH and VAL are stacked inside 7 cents and why every confirmation test above is currently unusable. One line:

// last-bar block: let every engine use the Ticks Per Row lattice
float tick = syminfo.mintick * ticksPerRowInput

// and in f_fpViewRows, use the same step so Footprint rows land on it
int k = int(math.round(row.up_price() / (syminfo.mintick * ticksPerRowInput)))

Then set Ticks Per Row 50, Ticks Above/Below 32 → a $32 frame, roughly two average bars. The same change fixes a latent bug: today, Footprint mode with TPR above 1 leaves most frame rows permanently empty, because the rows arrive TPR ticks apart onto a one-tick lattice.
